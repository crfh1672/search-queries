# מערך שאילתות לבדיקת חיפוש סמנטי

כל רשומה כוללת שאילתה, קטע מקור נכון, קטע קרוב אך שגוי, ציטוטים ומיקומים מדויקים. המאגר מיועד למדוד חיפוש סמנטי ולהשוות אותו לחיפוש לקסיקלי, לא רק לאסוף שאלות לדוגמה.

## מקור אמת מחייב

**כל שאילתה וכל ציטוט חייבים להתבסס על קובץ ספר אמיתי מתוך [Otzaria/otzaria-library](https://github.com/Otzaria/otzaria-library), כולל ספרים שיובאו לשם ממאגרים חיצוניים.** הבודק דוחה מקור שמצביע לריפו אחר, לקובץ שאינו `.txt`, או לנתיב שאינו מתחת ל-`ספרים/אוצריא/` במאגר אוצריא.

הטקסט עצמו אינו מועתק למאגר השאילתות. כל מערך שומר את נתיב המקור, קומיט מדויק ו-SHA-256; הבודק מושך את אותו קובץ בדיוק או משתמש במטמון שאומת מול ה-hash.

## מבנה התיקיות

הקטגוריה נגזרת מהתיקייה הראשונה שמתחת ל-`ספרים/אוצריא/` בנתיב הספר בספריית אוצריא, למשל `תלמוד בבלי`, `שות`, `הלכה`, `משנה`, `מדרש` או `תנך`.

```
drafts/                              # לפני אישור ידני
  <קטגוריית אוצריא>/
    <שם הספר>/
      <שם הספר>.jsonl                # קובץ הנתונים הקנוני
      <שם הספר>.csv                  # נוצר אוטומטית מה-JSONL
      <שם הספר>.מקור.json             # פרטי המקור וה-hash

datasets/                            # אחרי אימות ואישור
  <קטגוריית אוצריא>/
    <שם הספר>/
      <שם הספר>.jsonl
      <שם הספר>.csv
      <שם הספר>.מקור.json

schema/query.schema.json             # סכמת רשומה
schema/source.schema.json            # סכמת פרטי המקור
tools/source_refs.py                 # הפקת מראה מקום ממסלול הכותרות
tools/validate.py                    # אימות מקור, מראי מקום, ציטוטים ו-CSV
tools/promote_dataset.py             # העברה מוגנת מטיוטה לנתונים מאושרים
tools/fetch_source.py                # איתור שאילתות שמושפעות מעדכון מקור
tools/update_sources.py              # רענון שמרני של הפניות לשורות
tools/score.py                       # Recall@K ו-MRR
tests/                               # בדיקות אוטומטיות
```

שם תיקיית הספר חייב להיות זהה לבסיס שם הקובץ ב-Otzaria (שם קובץ ה-`.txt` בלי הסיומת). קטגוריית התיקייה חייבת להתאים לקטגוריה בנתיב המקור. אין צורך לשכפל קובץ אחד בכל קטגוריה: המערכת שומרת קטגוריה אחת שמייצגת את מיקום הספר בספריית אוצריא.

## שיטת מראי המקום: כותרות במקום הנחת דף

קובצי הספרים של אוצריא משתמשים בכותרות HTML כגון `<h1>` עד `<h6>`. הבודק מפיק לכל שורה את מסלול הכותרות הפעיל, לדוגמה:

- `הלכות ציצית > סימן א`
- `שאלות ותשובות > סימן א`
- בספר תלמוד: `דף ב.` או `דף ב:`, לפי הכותרת שבקובץ.

המסלול נבנה מהכותרות עצמן, לפני הסרת תגי HTML. מספרי השורות נשארים מספרים מוחלטים בקובץ המקור המלא, לאחר אותו נרמול טקסט המשמש לבדיקת הציטוטים. כך השיטה מתאימה לספרי שו"ת, הלכה, משנה, תלמוד וסוגי ספרים נוספים בלי להעמיד פנים שכל מקור מחולק לדפים.

אם טווח ציטוט עובר בין שתי כותרות שונות, או שהמסלול שב-JSONL אינו תואם לכותרת שבשורה שצוינה, הבדיקה נכשלת. כותרות שחסרה בהן היררכיה נשארות במסלול שהבודק יכול להסיק מהכותרות בפועל; הוא אינו מנחש מספרי דף או סימן.

## מבנה הרשומה

כל שורת JSONL מכילה בדיוק 12 שדות מחרוזת בסדר הזה:

1. `id`
2. `query`
3. `type`
4. `correct_ref`
5. `correct_quote`
6. `correct_line`
7. `near_miss_ref`
8. `near_miss_quote`
9. `near_miss_line`
10. `near_miss_same_section`
11. `split`
12. `verified_by_human`

`correct_ref` ו-`near_miss_ref` הם מסלולי הכותרות כפי שהבודק מפיק אותם. `correct_line` ו-`near_miss_line` הם שורות מוחלטות או טווחי שורות כגון `12-13`. `near_miss_same_section` חייב להיות `"כן"` בדיוק כאשר שני מראי המקום זהים, אחרת `"לא"`. הציטוטים חייבים להיות מדויקים, נוכחים בשורות המוצהרות, ולא לחפוף.

הערכים המותרים ל-`type` הם `conceptual` ו-`short`; ל-`split` — `train` ו-`test`. המזהה ייחודי ובפורמט `<id_prefix>-NNN`. JSONL הוא מקור האמת; CSV חייב להיווצר ממנו ולהיות זהה לו.

## פרטי המקור: `<שם הספר>.מקור.json`

המטא־נתונים כוללים בדיוק:

- `book_name` — שם הספר, זהה לבסיס שם הקובץ ולשם תיקיית המערך.
- `source_category` — הקטגוריה הראשונה מתחת ל-`ספרים/אוצריא/` בנתיב הספר.
- `id_prefix` — קידומת מזהי הרשומות, באנגלית באותיות קטנות.
- `origin_repo` — חייב להיות `https://github.com/Otzaria/otzaria-library`.
- `origin_path` — נתיב יחסי מדויק לקובץ הספר `.txt`, כולל `ספרים/אוצריא/`.
- `origin_commit` — SHA מלא בן 40 תווים של קומיט בספרייה.
- `origin_sha256` — SHA-256 בן 64 תווים של הקובץ הגולמי באותו קומיט.
- `note` — הערה חופשית.

אסור להמציא נתיב, קומיט, hash, כותרת, ציטוט או מספר שורה. בעת הכנת מטא־נתונים יש לקחת את הנתיב מתוך ספריית אוצריא ולחשב את ה-hash של הקובץ באותו קומיט מדויק. אין להסתמך על `main` המשתנה בלי להצמיד קומיט.

## תהליך עבודה: טיוטה → בדיקה → אישור

1. בוחרים ספר קיים מתוך ספריית אוצריא ומאמתים את נתיבו ואת הכותרות בקובץ ה-`.txt` המקורי.
2. יוצרים `drafts/<קטגוריה>/<שם הספר>/` עם קובצי JSONL, CSV ומטא־נתונים.
3. מריצים את הבודק ומתקנים שגיאות. `verified_by_human` יכול להישאר ריק בטיוטה.
4. אדם בודק את משמעות השאילתה, את הציטוט הנכון ואת ה-`near miss` (שאינו באמת עונה לשאילתה).
5. ממלאים `verified_by_human` בשם/מזהה הבודק ומריצים:

```bash
python tools/promote_dataset.py "drafts/שות/שם הספר"
```

הכלי מעביר את המערך אל `datasets/<קטגוריה>/<שם הספר>/` רק אם הבדיקות עוברות, האימות הידני מלא והיעד עדיין אינו קיים. הוא אינו יוצר עותק מתחרה או דורס מערך מאושר קיים.

## פקודות שימושיות

בדיקת כל הטיוטות והמערכים המאושרים:

```bash
python tools/validate.py
python -m unittest discover -s tests -v
```

בדיקת מערך אחד:

```bash
python tools/validate.py "drafts/שות/שם הספר"
python tools/validate.py "datasets/שות/שם הספר"
```

בדיקה ללא רשת, כשמקור הספר כבר נמצא במטמון ותואם ל-hash:

```bash
python tools/validate.py --offline
```

השוואת קובץ נעוץ עם גרסה אחרת של המקור והצגת שאילתות שנוגעות בשורות ששונו:

```bash
python tools/fetch_source.py "datasets/שות/שם הספר" --ref main
```

מדידת Recall@K ו-MRR:

```bash
python tools/score.py --template results.csv
python tools/score.py results.csv
```

JSONL הוא הקובץ הקנוני; לאחר שינוי בו יש לחדש את ה-CSV ממנו. בדיקות GitHub Actions רצות בכל push ובכל pull request.

## תחזוקת מקורות

`tools/update_sources.py` מחפש מערכים מקוננים תחת `datasets/`. הוא מעדכן מראי מקום ומספרי שורות רק כאשר הציטוטים עוברים למיקום חדש באופן חד־משמעי. אם הציטוט השתנה, נעלם או הפך עמום, המערך נשאר ללא שינוי ונכתב דוח לבדיקת אדם.

## רישוי ומקור

העובדה שספר נמצא ב-Otzaria אינה אומרת שלכל הספרים יש רישיון זהה. הספרייה כוללת טקסטים ממקורות שונים, וחלק מהמקורות עשויים לדרוש ייחוס, להגביל שימוש מסוים או לחייב אישור. לפני הפצה ציבורית או שילוב במוצר יש לבדוק את רישיון הספר הספציפי לפי מסמכי אוצריא והמקור שממנו יובא. המאגר שומר הפניה למקור, לא עותק של הטקסט עצמו.

## מגבלות איכות

בדיקות אוטומטיות מאשרות מבנה, מקור, hash, מיקום הציטוט והתאמה למסלול הכותרות. הן אינן מוכיחות שהשאילתה טבעית או שה-`near miss` אכן אינו עונה עליה. אלה מחייבים בדיקה אנושית, ונתונים לא נחשבים מאושרים רק מפני שה-CI ירוק.
