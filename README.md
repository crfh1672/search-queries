# מערך שאילתות לבדיקת חיפוש סמנטי

כל רשומה כוללת שאילתה, קטע מקור נכון, קטע קרוב אך שגוי, ציטוטים ומיקומים מדויקים. המאגר מיועד למדוד חיפוש סמנטי ולהשוות אותו לחיפוש לקסיקלי, לא רק לאסוף שאלות לדוגמה.

## מקור אמת מחייב

**כל שאילתה וכל ציטוט חייבים להתבסס על קובץ ספר אמיתי מתוך [Otzaria/otzaria-library](https://github.com/Otzaria/otzaria-library), כולל ספרים שיובאו לשם ממאגרים חיצוניים.** הבודק דוחה מקור שמצביע לריפו אחר, לקובץ שאינו `.txt`, או לנתיב שאינו מתחת ל-`<שורש ארוז>/ספרים/אוצריא/` במאגר אוצריא.

הטקסט עצמו אינו מועתק למאגר השאילתות. כל מערך שומר את נתיב המקור, קומיט מדויק ו-SHA-256; הבודק מושך את אותו קובץ בדיוק או משתמש במטמון שאומת מול ה-hash.

### רק מה שאוצריא באמת מפיצה

במאגר `otzaria-library` יש הרבה עותקי טקסט שאינם נכנסים לספרייה שמגיעה למשתמשים. רק השורשים שב-`BOOK_ROOTS` של בניית השחרור (`manual_links_packaging.py` באוצריא) נארזים, והם רשומים ב-`PACKAGED_ROOTS` ב-`tools/library.py`. `origin_path` חייב להיות `<שורש ארוז>/ספרים/אוצריא/<קטגוריה>/…/<ספר>.txt`. נדחים בין השאר: `extraBooks/`, `docxToOtzaria/`, `DictaToOtzaria/לא ערוך/`, ותיקיות כמו `ספרים/לא ממויין/`.

שורש מאוחר ברשימה דורס שורש מוקדם עם אותו נתיב יחסי. לכן, כשהבודק רץ עם רשת, הוא בודק בקומיט הנעוץ שאין עותק באותו נתיב יחסי בשורש מאוחר, ודוחה מקור שנדרס. התשובה נשמרת במטמון. עם `--offline` ובלי תשובה שמורה הבדיקה מדולגת במערכי `drafts/`, אבל נכשלת במערך מאושר (`datasets/` וקידום), כדי שלא יאושר מקור שלא נבדק. אם הרשימה באוצריא משתנה, יש לעדכן את `PACKAGED_ROOTS`; בדיקה מוודאת שהסכמה תואמת אותה.

## מבנה התיקיות

הקטגוריה נגזרת מהתיקייה הראשונה שמתחת ל-`ספרים/אוצריא/` בנתיב הספר בספריית אוצריא, למשל `תלמוד בבלי`, `שות`, `הלכה`, `משנה`, `מדרש` או `תנך`.

```
drafts/                              # לפני אישור ידני
  <קטגוריית אוצריא>/
    <שם הספר>/
      <שם הספר>.jsonl                # קובץ הנתונים הקנוני
      <שם הספר>.csv                  # נוצר אוטומטית מה-JSONL
      <שם הספר>.מקור.json             # פרטי המקור וה-hash

datasets/                            # אחרי אימות ואישור
  <קטגוריית אוצריא>/
    <שם הספר>/
      <שם הספר>.jsonl
      <שם הספר>.csv
      <שם הספר>.מקור.json

schema/query.schema.json             # סכמת רשומה
schema/source.schema.json            # סכמת פרטי המקור
verifiers.txt                        # שמות המאמתים המורשים (אחד בשורה)
tools/source_refs.py                 # הפקת מראה מקום ממסלול הכותרות
tools/validate.py                    # אימות מקור, מראי מקום, ציטוטים ו-CSV
tools/promote_dataset.py             # העברת טיוטה מאומתת אל datasets/
tools/pathsafe.py                    # סירוב לקישורים סמליים (עזר משותף)
tools/fetch_source.py                # איתור שאילתות שמושפעות מעדכון מקור
tools/update_sources.py              # רענון שמרני של הפניות לשורות
tools/score.py                       # Recall@K ו-MRR
tests/                               # בדיקות אוטומטיות
```

שם תיקיית הספר חייב להיות זהה לבסיס שם הקובץ ב-Otzaria (שם קובץ ה-`.txt` בלי הסיומת). קטגוריית התיקייה חייבת להתאים לקטגוריה בנתיב המקור. אין צורך לשכפל קובץ אחד בכל קטגוריה: המערכת שומרת קטגוריה אחת שמייצגת את מיקום הספר בספריית אוצריא.

## שיטת מראי המקום: כותרות במקום הנחת דף

קובצי הספרים של אוצריא משתמשים בכותרות HTML כגון `<h1>` עד `<h6>`. הבודק מפיק לכל שורה את מסלול הכותרות הפעיל, לדוגמה:

- `הלכות ציצית > סימן א`
- `שאלות ותשובות > סימן א`
- בספר תלמוד: `דף ב.` או `דף ב:`, לפי הכותרת שבקובץ.

רק שורות שמתחילות ב-`<h1>`–`<h6>` הן כותרות, כמו בתוכן העניינים של אוצריא; שורה שמתחילה ב-`#` היא טקסט רגיל. כותרת `<h1>` היא שם הספר, והשורות שתחתיה בלי כותרת עמוקה יותר מצוטטות כ-`פתיחת הספר`. כותרת שמדלגת על רמה (h2 ואז h4) מתחברת להורה הקרוב ביותר שרמתו קטנה משלה, כמו באוצריא, וכותרת שלפניה רווח נחשבת כותרת רגילה. שורה שמתחילה ב-`#` נחשבת טקסט רגיל, כפי שבונה הספרייה (`generator.dart`) קורא אותה. כותרת עם `data-toc="none"` אינה חלק מהמסלול.

המסלול נבנה מהכותרות עצמן, לפני הסרת תגי HTML. מספרי השורות נשארים מספרים מוחלטים בקובץ המקור המלא, לאחר אותו נרמול טקסט המשמש לבדיקת הציטוטים. כך השיטה מתאימה לספרי שו"ת, הלכה, משנה, תלמוד וסוגי ספרים נוספים בלי להעמיד פנים שכל מקור מחולק לדפים.

אם טווח ציטוט עובר בין שתי כותרות שונות (או בין שני מקטעים נפרדים באותו שם), או שהמסלול שב-JSONL אינו תואם לכותרת שבשורה שצוינה, הבדיקה נכשלת. הבודק אינו מנחש מספרי דף או סימן.

כותרת פגומה (ריקה, תג שלא נסגר, או כותרת עם רווח בתחילת השורה) אינה מפילה את הספר כולו. השורות שמתחתיה, עד כותרת `<h1>` או כותרת `<h2>` הבאה שנכללת בתוכן העניינים (לא `data-toc="none"`), נחשבות לא ודאיות: ציטוט שנשען עליהן נדחה והשגיאה מצביעה על השורה הפגומה, וכל שאר הספר נשאר שמיש.

## מבנה הרשומה

כל שורת JSONL מכילה בדיוק 12 שדות מחרוזת בסדר הזה:

1. `id`
2. `query`
3. `type`
4. `correct_ref`
5. `correct_quote`
6. `correct_line`
7. `near_miss_ref`
8. `near_miss_quote`
9. `near_miss_line`
10. `near_miss_same_section`
11. `split`
12. `verified_by_human`

`correct_ref` ו-`near_miss_ref` הם מסלולי הכותרות כפי שהבודק מפיק אותם. `correct_line` ו-`near_miss_line` הם שורות מוחלטות או טווחי שורות כגון `12-13`. `near_miss_same_section` חייב להיות `"כן"` בדיוק כאשר שני הציטוטים נמצאים באותו מקטע, אחרת `"לא"`. שני מקטעים אחים עם אותה כותרת (למשל שתי `<h3>הלכה א</h3>`) נותנים מראי מקום זהים אבל הם מקטעים שונים, ולכן הערך הוא `"לא"`. הציטוטים חייבים להיות מדויקים, נוכחים בשורות המוצהרות, ולא לחפוף.

הערכים המותרים ל-`type` הם `conceptual` ו-`short`; ל-`split` — `train` ו-`test`. המזהה בפורמט `<id_prefix>-NNN`, וייחודי בכל המערכים (טיוטות ומאושרים). גם `id_prefix` ייחודי לכל ספר, והבודק נכשל על התנגשות. JSONL הוא מקור האמת; CSV חייב להיווצר ממנו ולהיות זהה לו.

## פרטי המקור: `<שם הספר>.מקור.json`

המטא־נתונים כוללים בדיוק:

- `book_name` — שם הספר, זהה לבסיס שם הקובץ ולשם תיקיית המערך.
- `source_category` — הקטגוריה הראשונה מתחת ל-`ספרים/אוצריא/` בנתיב הספר.
- `id_prefix` — קידומת מזהי הרשומות, באנגלית באותיות קטנות.
- `origin_repo` — חייב להיות `https://github.com/Otzaria/otzaria-library`.
- `origin_path` — נתיב יחסי מדויק לקובץ הספר `.txt`: `<שורש ארוז>/ספרים/אוצריא/<קטגוריה>/…`, למשל `MoreBooks/ספרים/אוצריא/…`.
- `origin_commit` — SHA מלא בן 40 תווים של קומיט בספרייה.
- `origin_sha256` — SHA-256 בן 64 תווים של הקובץ הגולמי באותו קומיט.
- `note` — הערה חופשית.

אסור להמציא נתיב, קומיט, hash, כותרת, ציטוט או מספר שורה. בעת הכנת מטא־נתונים יש לקחת את הנתיב מתוך ספריית אוצריא ולחשב את ה-hash של הקובץ באותו קומיט מדויק. אין להסתמך על `main` המשתנה בלי להצמיד קומיט.

## תהליך עבודה: טיוטה → בדיקה → אישור

1. בוחרים ספר קיים מתוך ספריית אוצריא ומאמתים את נתיבו ואת הכותרות בקובץ ה-`.txt` המקורי.
2. יוצרים `drafts/<קטגוריה>/<שם הספר>/` עם קובצי JSONL, CSV ומטא־נתונים.
3. מריצים את הבודק ומתקנים שגיאות. `verified_by_human` יכול להישאר ריק בטיוטה.
4. אדם בודק את משמעות השאילתה, את הציטוט הנכון ואת ה-`near miss` (שאינו באמת עונה לשאילתה).
5. הבודק רשום ב-`verifiers.txt` (שורה לשם; שורות שמתחילות ב-`#` הן הערות). רק אחרי שהשווה בפועל כל רשומה למקור, ממלאים `verified_by_human` בשמו בדיוק כפי שנרשם, ומריצים:

```bash
python tools/promote_dataset.py "drafts/שות/שם הספר"
```

הכלי מעביר את המערך אל `datasets/<קטגוריה>/<שם הספר>/` רק אם הבדיקות עוברות, כל רשומה נושאת מאמת מ-`verifiers.txt` והיעד עדיין אינו קיים. הוא אינו דורס מערך קיים, והמעבר הוא `rename` פשוט שגיט רושם. ה-CI בודק שוב את התוצאה ב-pull request.

הרשימה ב-`verifiers.txt` היא רק שכבה ראשונה: מחרוזת בשדה אינה הוכחה לכך שאדם בדק. מומלץ להגדיר ב-GitHub גם CODEOWNERS ו-branch protection על `datasets/**` כך שמאמת שאינו הכותב יאשר את ה-PR.

## פקודות שימושיות

בדיקת כל הטיוטות והמערכים המאושרים:

```bash
python tools/validate.py
python -m unittest discover -s tests -v
```

בדיקת מערך אחד:

```bash
python tools/validate.py "drafts/שות/שם הספר"
python tools/validate.py "datasets/שות/שם הספר"
```

בדיקה ללא רשת, כשמקור הספר כבר נמצא במטמון ותואם ל-hash:

```bash
python tools/validate.py --offline
```

השוואת קובץ נעוץ עם גרסה אחרת של המקור והצגת שאילתות שנוגעות בשורות ששונו:

```bash
python tools/fetch_source.py "datasets/שות/שם הספר" --ref main
```

מדידת Recall@K ו-MRR:

```bash
python tools/score.py --template results.csv
python tools/score.py results.csv
```

JSONL הוא הקובץ הקנוני; לאחר שינוי בו יש לחדש את ה-CSV ממנו. בדיקות GitHub Actions רצות בכל push ובכל pull request, על Linux ועל Windows.

## תחזוקת מקורות

`tools/update_sources.py` מחפש מערכים מקוננים תחת `datasets/`. הוא מעדכן מראי מקום ומספרי שורות רק כאשר הציטוטים עוברים למיקום חדש באופן חד־משמעי. אם הציטוט השתנה, נעלם או הפך עמום, המערך נשאר ללא שינוי ונכתב דוח לבדיקת אדם.

## מעבר ממערכים ישנים

מערך שנכתב לפני המעבר לכותרות (שדות `masechet`, מראי מקום כמו `מסכת ב ע"א`, `near_miss_same_amud`) צריך: להחליף את `masechet` ב-`book_name` ולהוסיף `source_category`; לכוון את `origin_path` לעותק שאוצריא מפיצה (`<שורש ארוז>/ספרים/אוצריא/...`) ולחשב מחדש את `origin_commit` ואת `origin_sha256` עליו; להחליף כל מראה מקום במסלול הכותרות של השורה (`python tools/validate.py` מדפיס את המסלול הצפוי לכל רשומה שגויה); לשנות את שם העמודה ל-`near_miss_same_section` ולבדוק שהערך נכון לפי מקטעים; ולהעביר את התיקייה אל `drafts/<קטגוריה>/<ספר>/` לאישור מחדש. אם הטקסט היחיד שנמצא נמצא רק תחת שורש שאינו נארז (למשל `extraBooks/` או `ספרים/לא ממויין/`), אי אפשר לבסס עליו מערך עד שהספר ייכנס לספרייה המשוחררת.

## רישוי ומקור

העובדה שספר נמצא ב-Otzaria אינה אומרת שלכל הספרים יש רישיון זהה. הספרייה כוללת טקסטים ממקורות שונים, וחלק מהמקורות עשויים לדרוש ייחוס, להגביל שימוש מסוים או לחייב אישור. לפני הפצה ציבורית או שילוב במוצר יש לבדוק את רישיון הספר הספציפי לפי מסמכי אוצריא והמקור שממנו יובא. המאגר שומר הפניה למקור, לא עותק של הטקסט עצמו.

## מגבלות איכות

בדיקות אוטומטיות מאשרות מבנה, מקור, hash, מיקום הציטוט והתאמה למסלול הכותרות. הן אינן מוכיחות שהשאילתה טבעית או שה-`near miss` אכן אינו עונה עליה. אלה מחייבים בדיקה אנושית, ונתונים לא נחשבים מאושרים רק מפני שה-CI ירוק.
